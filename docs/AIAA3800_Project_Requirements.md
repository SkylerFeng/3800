# AIAA 3800 Final Project：视障辅助智能交互眼镜

## 1. 项目目标

开发一套面向视障人士的可穿戴辅助原型，结合摄像头、麦克风、距离传感器、IMU、震动反馈与视觉/语言模型，实现环境问答、物体方位提示、近距离障碍预警，以及基于高德地图的道路导航辅助。

本项目定位为课程原型，不替代盲杖、导盲犬或专业出行辅助工具，也不承诺独立保障道路通行安全。

## 2. 核心功能需求

| 功能 | 用户需求 | 预期输出 |
| --- | --- | --- |
| 场景问答 | 询问“眼前有什么”“杯子是什么颜色” | 根据当前画面给出简短语音回答 |
| 物体方位提示 | 询问“杯子在哪里”，辅助寻找和拿取 | 提示左、右、前方等相对方位；距离仅在有可靠依据时提供 |
| 障碍预警 | 及时感知前方近距离障碍 | 根据测距结果触发不同震动节奏或强度 |
| 道路导航 | 前往指定目的地 | 高德地图提供路线与转向信息，LLM转换为简洁的语音提示 |

### 2.1 场景理解与语音交互

- 获取摄像头画面，接收用户语音问题。
- 将语音识别为文本，结合画面调用视觉模型或多模态大模型。
- 通过语音输出回答，形成“提问—感知—分析—反馈”的交互闭环。
- 看不清或无法确认时明确说明，不编造物体、颜色或位置。

### 2.2 物体定位与拿取辅助

- 识别常见目标，并给出相对于当前摄像头视角的方向。
- 初期以“杯子在画面右侧”等粗粒度提示为主。
- 头部朝向不一定等于身体朝向，应明确方位参照系。
- 精确的手部移动量需要手部追踪、空间标定和可靠测距，暂不作为已实现能力。
- 单个超声波读数不能直接视为画面中指定杯子的距离。

### 2.3 障碍检测与震动预警

- 持续读取前方距离，按实验确定的阈值触发分级震动。
- 优先在ESP32S3本地完成测距判断与震动控制，使预警不依赖LLM响应。
- 区分有效测量、过期数据、无目标及传感器故障，不能将无效数据解释为前方安全。
- 该功能仅覆盖传感器有效探测范围，不代表可检测所有障碍、台阶或坑洞。

### 2.4 高德地图与LLM道路导航

- 获取用户位置和目的地；定位来源计划使用手机，具体接入方式待确定。
- 由高德地图提供路线、距离和转向信息。
- LLM负责理解用户意图和整理提示，不自行生成未经地图支持的路线。
- 地图负责路线级导航，传感器负责近距离障碍提示，两者不能相互替代。
- 不凭LLM判断“可以安全过马路”；演示应在受控环境、有人陪同下进行。

## 3. 现有硬件与用途

| 硬件 | 主要用途 |
| --- | --- |
| Seeed Studio XIAO ESP32S3 Sense | 眼镜端采集、通信和本地控制 |
| 摄像头 | 场景图像获取与视频流传输 |
| 麦克风 | 采集用户语音 |
| YB-MRA02-V10 IMU | 提供姿态信息，探索头部朝向辅助 |
| A22超声波测距模块 | 前方障碍测距 |
| DRV2605L与LRA震动马达 | 触觉反馈 |
| 扩展板及连接线 | 模块连接与接口扩展 |

语音播放设备、便携供电和最终佩戴结构仍需确认。麦克风本身不能承担语音播放。

## 4. 系统分工与通信

采用“眼镜端采集与实时预警 + 手机/电脑端模型处理”的设计方向，模型是否本地部署或调用云端API尚未最终确定。

| 层级 | 职责 |
| --- | --- |
| ESP32S3眼镜端 | 摄像头与音频采集、IMU/超声波读取、震动控制、连接状态管理 |
| 手机或电脑端 | 数据接收、语音识别、视觉/LLM调用、地图接入、语音合成 |
| 模型与地图服务 | 场景理解、问题回答、路线规划与指令整理 |

现有工程为 `XIAO_ESP32S3_Stream`，包含以下通信与控制接口：

- HTTP MJPEG：摄像头视频流。
- TCP双向通道：传感器、状态、PCM音频及控制指令。
- BOOT按键：触发录音。
- Wi-Fi自动重连。
- 远程震动控制接口。

## 6. 开发优先级

### 第一阶段：打通基础硬件

1. 保持视频流与超声波回传稳定。
2. 修复震动模块，实现“距离变化—震动变化”。
3. 单独测试IMU，再整合到主工程。
4. 验证录音、数据传输和语音播放路径。

### 第二阶段：完成核心交互闭环

1. 接入语音识别、视觉模型/LLM和语音合成。
2. 完成颜色问答、场景描述和粗粒度物体方位提示。
3. 确保模型调用期间不阻塞本地障碍预警。
4. 处理网络中断、模型超时、无效传感器数据和无法识别等情况。

### 第三阶段：扩展与演示

1. 接入手机定位及高德地图路线信息。
2. 探索IMU辅助方位解释和更可靠的目标距离估计。
3. 完成佩戴、供电和受控场景测试。

## 7. 测试与最终展示

建议用三个场景展示核心价值：

1. **障碍预警**：改变障碍距离，观察震动等级及响应。
2. **物体问答**：询问杯子颜色与相对位置，获得语音回答。
3. **路线导航**：在陪同下演示一段受控路线，输出地图支持的导航提示。

测试记录应包括问答正确率、方位提示正确率、端到端响应时间、预警延迟、误报/漏报情况，以及断网时的行为。具体验收阈值待小组根据课程要求和实测结果确定。

## 8. 尚需确定的事项

- 模型/API选择及运行位置。
- 手机或电脑如何承担主处理端。
- 语音播放设备与音频输出路径。
- 高德地图定位和导航接入方案。
- 便携供电、续航、安装和佩戴方式。
- 分级预警阈值、功能验收标准及组员分工。

## 一句话概括

通过可穿戴传感器获取环境信息，利用视觉与语言模型完成自然交互，并以本地震动预警和地图导航提示辅助视障人士感知环境与行动。
