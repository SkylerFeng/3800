# AIAA 3800 项目目标与工作记录

## 最终交互形态

3800 自己提供面向眼镜的语音智能体。用户在手机上打开 3800 助手并授权后，可以用普通话提问、选择目的地、确认路线、开始或暂停导航。语音识别、对话状态、工具调用和确认都由 3800 管理，无需设置或唤起手机自带助手。手机负责麦克风、定位和播放。模型可先运行在当前电脑端或使用已配置的千问视觉服务，手机端推理作为独立部署选项评估。

| 用户说 | 3800 智能体的行为 |
| --- | --- |
| 「杯子在哪里？」 | 获取眼镜最新可用画面，经授权调用视觉模型，用普通话播报画面中的方位。 |
| 「步行去图书馆」 | 使用手机定位查询地点，读出少量候选，保留完整候选供用户继续查询。 |
| 「第二个」 | 在当前候选中选择第二项，调用地图规划，读出目的地和路线摘要。 |
| 「确认出发」「暂停导航」 | 按当前对话状态执行对应操作。具体转向来自地图，定位失效时暂停播报。 |

高德为智能体提供地点和路线。默认目标是在 3800 内完成路线确认和步行提示。用户也可选择将终点交给高德 App，由可用的官方接口决定能够交接到哪个环节。声纳预警继续独立运行。

验收时，从打开助手并完成权限授权开始，分别用语音走完眼镜问答和多轮步行导航。另测错听、候选过期、无有效位置及取消，确保助手能提示重试并停止执行旧指令。锁屏唤醒、后台持续收音和手机端模型属于独立能力。前台网页已实现首版多轮语音闭环，验证范围见迭代 7。

课程验收目标是在受控环境完成四个场景：用眼镜画面回答场景问题和物品颜色，用画面左／中／右说明目标位置，用真实超声波触发确定性分级预警，以及沿地图返回的步行路线更新提示。语音问答由眼镜 BOOT 键采集，经本地中文识别、用户确认、视觉模型和电脑端播报闭环。IMU 独立显示姿态与新鲜度，安装标定完成前不参与导航方向或物体距离判断。

| --- | --- |

| 2. 接入真机 | 在 3800 显示真实画面、距离、IMU 和模块健康；断线和过期后降级；震动按 ACK 报告 |
| 3. 闭合语音 | TCP 录音组装、中文识别、可确认的问答、网页播放；地图播报与障碍优先 |

## 迭代 1 · 2026-11-22

已阅读项目需求和本地 `XIAO_ESP32S3_Stream` 的协议与关键实现。对 `192.168.20.155:9000` 做只读采样，收到 CRC 正确的 v3 IMU 68 帧、A22 25 帧及状态 1 帧。HTTP 视频与 TCP 独立，TCP 只能有一个客户端。协议字段以下载工程的 `PROTOCOL.md`、`TransportProtocol.h`、`SensorManager.cpp` 和 `CommandHandler.cpp` 为依据。运行软件时不需要下载目录。

| 接口 | 约定 |
| --- | --- |
| HTTP GET /stream | MJPEG，每部分有 JPEG Content-Length |
| TCP 9000 | 小端 28 字节头，XIAO 魔数、v3、类型、标志、序号、开机微秒、长度、载荷 CRC32 |
| IMU 0x10 | 4 个 WXYZ 四元数分量和 3 个弧度 RPY |
| A22 0x11 | 固件换算后的毫米、原始值、状态及原始单位 |
| 音频 0x12 | 流 ID、连续分片索引、采样率、样本数及格式；START/MORE/END 标志 |
| 健康 0x13 | 运行时间、空闲堆、RSSI 和模块标志 |
| 命令 0x20 / ACK 0x21 | JSON，ACK 通过 rx_sequence 对应请求；驱动状态与实体振动分别验收 |

设备时间记录为开机时间，数据过期依据主机单调时钟。停用软件、断开电脑后的预警需要固件自身具备规则，当前从现有固件的轮询和命令处理看，震动由主机命令驱动。

## 迭代 2 · 真机数据与预警

在 3800 中分别接入 MJPEG 和单一 TCP v3 会话。真机返回 320×240 JPEG，浏览器成功解码。连续 8 次状态读取中，图像编号持续变化，IMU 样本主机接收年龄约 0～0.04 秒，A22 报告有效距离约 0.159～0.162 米，规则进入紧急状态。设备健康帧报告 IMU、声纳和麦克风就绪，马达驱动未就绪。故障时页面显示驱动不可用。真实马达命令由 `HAPTIC_OUTPUT=esp32` 控制，需新鲜距离、就绪状态和匹配 ACK。实体振感需单独验收。网页可手动开启两级提示音。

TCP 本地测试复现拆包、粘包、CRC 错误、断线、遥测过期、匹配 ACK 和录音分片丢失。设备适配层直接实现公开的 v3 数据格式，运行时无需加载固件工程或旧 Python 客户端。

## 迭代 3 · 语音、文本与地图

- 音频接收核对 16 kHz、PCM16、单声道和连续分片，生成 Vosk 所需的 WAV。使用本地 Vosk 0.3.45 与中文模型 small-cn-0.22。对 eSpeak 生成的三条合成语音成功执行识别，约 1.0～1.6 秒，识别文字有错误。界面支持编辑后再提交。
- 根据用户现场条件，本轮用场景、颜色、方位和目的地的预设文本驱动。示例文本经普通提问或目的地入口提交。BOOT 录音保留为后续真机验收项。
- eSpeak NG 1.50 合成普通话 WAV。Chrome 测到回答和地图语音实际进入播放状态，暂停导航和近距离预警可清除旧播放。声卡音量和现场可懂度由展示人员核对。
- 千问用内置生成示意图测试。首个请求读取超时，重试在 4.81 秒返回「示意图中的杯子是蓝色的，位于画面的右侧。」相机画面发送由用户对每次提问确认。
- 高德使用公开示例坐标复测了搜索、坐标转换和步行路线，返回 8 个候选及一条 2450 米、6 步的路线。动态路线继续使用地图步骤和位置规则。目的地输入支持常用前缀，确认由用户完成。真实手机外场定位仍待测。

## 迭代 5 · 播报、测距和画面响应

- 真机与离线演示已启用本地 Piper 普通话。问答和路线都使用同一套播报设置。试听样本输出为 22,050 Hz 单声道 PCM WAV。浏览器验证了两种播报的播放进度，现场听感待用户核对。
- 区分声纳无回波、受干扰、超出配置区间和连接异常。低于有效下限的正读数触发紧急等级。无回波保留未知状态，数据过期即清空距离。当前近距离真机采样稳定在约 0.23 米，远端极限与无回波转变由协议样本验证，现场量程仍待测量。
- 实时预览独立于 500 毫秒的面板轮询，收到新帧即更新。Chrome 的六秒窗口从 12 帧增至 19 帧，新版帧间隔中位数 291 毫秒。ESP32 原始流六秒也收到 19 帧，中位数 295 毫秒。预览接口返回帧时的主机端帧龄中位数 1 毫秒、最大 32 毫秒，采集到显示的端到端延迟未测量。

109 项自动测试通过，离线问答、测距和导航的 Chrome 回归通过。调参入口见 [DEMO.md](DEMO.md)。

## 迭代 6 · 手机高德与普通话播报

增加手机麦克风经 HTTPS 到本机 Vosk 的目的地识别链路，核对文字后通过高德官方 URI 开启地点搜索或把已选终点交给高德步行导航。高德显示道路底图并维护 App 内的导航和播报。项目内候选增加到每页 20 个，最多 5 页。定位与搜索、路线规划分别处理，旧样本仍按既有精度和时效规则降级。

本机切换到 Sherpa-ONNX Matcha 中文音色，保留 Piper 可切换。用同一句导航提示本地合成，Matcha 约 1.2 秒，Piper 约 0.6 秒。手机 HTTPS 播报测试接口返回有效 22,050 Hz WAV，用时 1.33 秒。语音试听按钮允许独立验证声音，浏览器阻止自动播放时可点播放器。

114 项自动测试通过。系统 Chrome 手机尺寸验证了语音录制、Vosk 转写、高德搜索 URL 和音频播放器。转写使用测试音频并观察到个别误识别，界面允许修正。高德北京公开关键词搜索前两页均返回 20 个候选。vivo 实机 App 调起、导航播报和现场听感需在手机上验收。

## 迭代 7 · 3800 语音智能体

新增手机 HTTPS 助手页 /assistant。手机授予麦克风权限后，浏览器在前台判断语句停顿，将单句录音送给电脑的 Vosk。3800 根据对话状态调用眼镜画面、视觉服务或地图。Matcha 播完后恢复收音。地点选择和确认出发是两个独立步骤，导航状态变化会停止过时的转向播报。用户可以撤销位置或画面外发许可，也可结束会话。助手会话不写入磁盘。

系统 Chrome 使用合成录音模拟手机麦克风，从开启语音开始连续完成「带我去图书馆」「第二个」「确认出发」，到达模拟导航状态。另以实际 Vosk 验证「杯子在哪里」进入模拟视觉问答。测试期间使用独立本地服务，使用模拟画面和路线。真实手机权限流程与实际路线试走留待现场验证。助手使用当前千问视觉或已选模型，导航命令和确认由 3800 管理。

## 迭代 8 · Agent 协调多个功能

同一个语音入口识别画面问答、声纳测距、设备状态和导航请求，调用对应服务。复合指令按说出的顺序处理，支持「先告诉我障碍有多远，再看看杯子在哪里，然后带我去图书馆」。首版意图分析使用本地规则，视觉问答交给所选模型。遇到未知指令时播报可用操作。导航确认单独进行，实时路段播报继续遵循定位和障碍状态。

系统 Chrome 用合成录音和本地 Vosk 验证连续测距与画面问答，使用模拟画面和过期测距。并以测试数据验证近障碍读数、问答、候选搜索的顺序以及确认出发保护。
